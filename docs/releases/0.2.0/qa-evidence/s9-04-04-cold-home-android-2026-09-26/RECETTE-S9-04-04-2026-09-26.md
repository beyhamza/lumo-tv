## Dispositif

Compte neuf `qa.mobile.cold.20260926@test.example`, **une** source prête
`Banc à froid mobile` (`http://bench/playlist.m3u` + `http://bench/guide.xml`),
**zéro** lecture, **zéro** favori — c'est l'état « à froid » de la précision
produit du 26/09. Émulateurs `Pixel_10` (mobile) et `Television_1080p` (TV),
APK debug des deux shells, API `lumo-api` sur 8080, `adb reverse tcp:8080`.
Guide XMLTV relatif injecté dans `lumo-bench` (comme la passe du matin).

État local vidé (`pm clear`) avant chaque surface : les rails Android lisent
`Room`, donc un appareil neuf est la seule façon d'obtenir `rails.recents` vide.

## Verdict

| Surface | Verdict | Ce que l'accueil à froid montre | Les deux accès explicites |
|---|---|---|---|
| **Android mobile** (`tv.lumo.android.debug`) | ❌ **défaut** | « Nothing here yet » + 3 boutons **Live / Films / Series** | **absents** |
| **Android TV** (`tv.lumo.androidtv.debug`) | ❌ **défaut** | idem + rail de nav (Home, Live TV, Films, Series, My library, Settings) | **absents** |
| **Web** (main, `:3000`) | ❌ **bug #213 toujours présent** | panneau « Rien à reprendre pour l'instant » + **Direct / Films / Séries** | **absents** (`hasAll=0`, `hasGuide=0`) |

**Correction d'une observation antérieure.** La TV n'est **pas** correcte à
froid : l'accès du matin (« TV, ils sont là dès l'ouverture ») avait été mesuré
sur un compte **avec historique** (rail Live non vide). À froid réel, le même
`Blank(actions)` que le mobile s'affiche — `Live/Films/Series`, pas
`Toutes les chaînes` / `Guide TV`.

**Cause unique, lue dans le code** (`feature/home/…/HomeState.kt`,
`HomeMobileScreen.kt`, `HomeTvScreen.kt`) : les deux accès ne vivent que dans
`HomeSection.Live → ChannelRail(secondaryAction = "Guide TV")`, et une section
Live n'existe que si `recent` est non vide. À froid `HomeState.blank == true`,
donc c'est `Blank(actions)` (l'invitation aux trois catalogues) qui est rendue,
et le rail — donc les deux liens — n'existe pas. Le correctif web #213
(`keepEntriesWhenEmpty` sur le rail Live) n'a pas d'équivalent Android.

## Ce qui marche (à froid, mobile)

Les portes de secours fonctionnent — c'est pour ça que le défaut n'est pas un
cul-de-sac, mais il reste un écart au critère :

- Accueil → **Live** → écran Direct, onglets **Channels / Guide**, liste des
  chaînes + programme en cours ; **Guide** ouvre « En ce moment » avec de vraies
  données (`On now` / `Next`), `Chaîne 05` (sans `tvg_id`) sans programme.
- Captures : `mobile-pass/mob01-cold-home.png`, `mob02-live-from-home.png`,
  `mob03-guide-from-home.png`.

## Reproduire

```bash
# mobile
adb -s emulator-5554 install -r 'C:/dev/lumo-tv/apps/android/app-mobile/build/outputs/apk/debug/app-mobile-debug.apk'
adb -s emulator-5554 reverse tcp:8080 tcp:8080
adb -s emulator-5554 shell pm clear tv.lumo.android.debug
adb -s emulator-5554 shell monkey -p tv.lumo.android.debug -c android.intent.category.LAUNCHER 1
# se connecter avec le compte à froid, puis lire l'accueil

# TV : pm clear, am start -n tv.lumo.androidtv.debug/tv.lumo.androidtv.TvActivity,
# approuver le code via POST /v1/auth/device/approve {user_code}
```

Préparation du compte : `mobile-pass/setup-cold-source.mjs` (`setup.log`).
Vérif web : `web-pass/web-cold-check.mjs` → `web-pass/web-cold-main.log`
(`{"hasAll":0,"hasGuide":0}`).
